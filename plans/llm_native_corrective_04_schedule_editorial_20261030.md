# C04 — Newsletter profile updates, schedule idempotency and editorial selection quality

**Status:** IMPLEMENTED; local profile, schedule and selection tests pass. Real broker/restart and editorial inspection remain C05 gates.
**Parent:** [corrective pass](llm_native_corrective_pass_overview_20261030.md).
**Dependencies:** M3/M5 already implemented, C01 for combined migration. Live fanout additionally needs C03.
**Scope:** deterministic profile and edition behavior, bounded quality improvements, no expanded channel framework.

## Findings from current branch

- routes/admin/api/newsletter_profiles.py update_newsletter_profile() has schedules = data.get("schedules", []), then clears profile.schedules on every PUT. An admin changing only enabled, email_enabled, timezone, max_articles or min_impact silently removes existing schedule rows. Define a clear partial-update contract (PATCH) or require a complete schedules list for PUT; do not silently interpret omission as deletion.
- The same route validates times but accepts bool where integer weekdays may be expected (bool is an int subtype) and converts absent schedule enabled to true; it clears/resets rows rather than updating identities. Handle duplicate time, invalid timezone, stale settings client and concurrency. Have schedule presentation display exact effective IANA zone, next execution and DST rule.
- services/newsletter_editions.py select_articles() uses Article.created_at >= now - 36h. This is not the same as "published since last edition" and may omit relevant articles processed late or retain undesired old content. Prior-edition suppression is also a fixed 36h interval. Its greedy MMR-style score uses original_title word-set Jaccard and a small repeated-category penalty relative to raw impact scores; similar events with different titles can escape the overlap penalty and unified editions can become category dominated.
- services/newsletter_editions.py _editorial_text() uses the existing why_it_matters/TL;DR field, but derives the paragraph with a regex first-sentence extraction (or 700-character cut). It does not guarantee a grammatical, factual, useful short paragraph. Avoid always calling an LLM, but add deterministic validation and optional bounded editorial fallback for inadequate source text.
- services/newsletter_scheduler.py plans per-profile local wall-clock occurrences with first fall DST fold and spring gap skip, a 60-minute catch-up and a 10-minute stale-dispatched recovery. tasks/newsletter.py handles the dispatch. These rules need actual broker/restart/concurrency qualification; a task scheduled at the same time across worker restarts must not duplicate an edition or leave an occurrence forever marked dispatched.
- With independent profiles, the subscription UI and archives should reflect per-category controls; the global unified toggle must not implicitly disable category editions or enroll subscribers. Manual preview/publish must remain separate from scheduled delivery.

## Corrective tasks

### A. Profile mutation and timetable semantics

1. Replace ambiguous all-or-partial PUT behavior with a documented validated contract: either PATCH changes only supplied fields (recommended) and a separate explicit schedule replacement route, or PUT requires all fields including schedules. Absence means preserve existing schedules; [] explicitly means clear all. Keep existing UI compatible; add tests for toggling email only without losing 07:00/17:00.
2. Validate profile identity, enabled, email_enabled, timezone, schedule weekdays (exact ints 0–6, no bools), local time HH:MM, enabled flags (actual boolean, not truthiness), article cap, impact floor, and max eight slots. Support optimistic concurrency via policy_revision or a compare-and-set version to prevent two admins from overwriting each other's changes. Audit updates with before/after schedule sets, without leaking subscriber data.
3. Persist schedule row changes idempotently by stable natural (profile_id, local_time) identity. Avoid removing/recreating unrelated rows for a switch change. Show admin next three occurrences, weekday/DST notices, disabled status and operator zone. Disabled profiles create no new future editions; existing archive is immutable.
4. Verify all old schedule config locations (pipeline.yaml, config.py, services/admin_settings.py, Beat) are either read-only/deprecated or migrated with explicit precedence; no second live legacy daily task should fan out accidentally. Handle timezone changes to a profile after one edition that day with documented occurrence identity semantics; do not recreate previously published slot unexpectedly.

### B. Deterministic editorial selection

5. Use canonical published_at, not ingestion created_at, for inclusion and chronological newsworthiness, with a per-profile lookback tied to last published edition *and a bounded maximum* to handle missed slots. Avoid late-published stories being excluded solely because ingested earlier; optionally track source event date separately without equating it to publication time. Fixed lookback (e.g. 36 hours) can remain a documented ceiling, not the only window.
6. Normalize impact and diversity scores to comparable scales; dedup by canonical source URL and article/story cluster and/or bounded tag/embedding similarity when available. Prefer deterministic methods first, with a clear fallback when embeddings are absent; do not require a new vector service. A cross-category unified profile should have an explicit soft category-share rule or penalty that actually influences selection. Preserve high-impact unique events even when titles share terms.
7. Use a configured minimum importance/novelty gate: if only one valid story exists, publish a one-story edition or skip depending on documented profile policy. Do not invent filler or repeat yesterday's story to fill max_articles. Preserve article provenance. Record per-candidate score components/exclusion reason in admin-only diagnostics to make overlap tuning reproducible.
8. Render each item from frozen stored article fields as: headline, a concise one-line why_it_matters, one accurate short paragraph and article link. Validate sentence boundaries and meaningful length; if paragraph cannot be faithfully derived from existing structured article body/TL;DR, use a *bounded optional* LLM transform with strict article-only evidence, source/provenance checking and safe deterministic fallback. The model cannot select hidden articles, alter URLs or silently rewrite a published snapshot. No three-stage newsletter LLM by default.
9. Explicit correction/withdrawal remains a documented versioning behavior; public snapshot, email and REST/MCP render the exact ordered edition items. Do not mutate edition after subscriber delivery.

### C. Scheduler crash recovery and safety

10. Exercise plan_due_occurrences() and newsletter_slot_tick() with a fixed clock across process restarts, two Beat attempts and two concurrent workers. DB uniqueness is final arbiter. Verify stale dispatched records, queued-but-never-published, invalid timezone, disabled profile, publication failure and retry logic. Recover only bounded catch-up windows; never send historical accumulated emails after downtime without operator approval.
11. Set DST policy as one first-fold occurrence in fall and no nonexistent civil-time occurrence in spring, including next-slot UI/API. Assert independently enabled unified, AI and other categories at distinct/twice-daily times. Email distribution remains off until C03.
12. Fix admin preview and publish side effects separately: preview must not create an edition/occurrence/outbox or transmit email; manual publish-without-send creates a durable archive even with email disabled; explicit send requires profile+global consent gates. Test subscriber type mapping after category rename/removal.

## Acceptance and fixtures

- PATCH {email_enabled:true} preserves two schedule times, weekdays and timezone; PATCH schedules:[] removes only schedules. Stale policy_revision conflicts, malformed types reject without partial DB changes. UI shows next 07:00/17:00 correctly.
- Artificial clock: UTC-midnight crossover, New York DST spring/fall transition, profile timezone changed after first occurrence, double Beat tick and worker restart result in exactly one edition per eligible civil slot.
- Fixed corpus: identical URL, same event with different headlines, related event with similar title, high-impact unique story, low-impact filler, late-published older-ingested story, missing embeddings, missing why_it_matters, no eligible articles. Verify low overlap, acceptable category mix, no fabricated links and stable selection under input reordering.
- Quantify editorial quality, call count and latency using a small manually checked fixture set, not only passing code assertions. No excessive additional LLM passes: report when optional generation triggers and reasons; test fallback on LLM unavailable.
- HTML archive, REST/MCP newsletters, and a captured test email share the same frozen title, why-it-matters, paragraph and canonical URL; email adds only recipient-specific transport details. No hidden articles leak via edition generation.

## Implementation evidence — 2026-10-30

- Profile update preserves omitted schedules, explicitly clears on `schedules: []`, validates exact weekday integers/booleans, uses policy-revision compare-and-set, and updates schedules by `(profile_id, local_time)`. Admin form carries the revision. Focused regressions: `tests/test_newsletter_profile_mutations.py`.
- Edition selection uses `published_at`, suppresses stories since the last edition within a 36-hour ceiling, normalizes canonical URLs, normalizes impact rank before title/category diversity penalties, and uses stored sentence-bounded text only. The selector remains deterministic and does not call an LLM.
- The admin next-slot calculation handles IANA zones, first fold, and spring gaps. Local DST/idempotency coverage remains in `tests/test_llm_native_publication.py`; target Beat restarts and two-worker concurrent qualification are still C05 evidence gates. No low-overlap claim is made without editorial corpus inspection.
- Worker lifetime follow-up (2026-10-30): the development helper now runs web, Celery worker and Beat beneath one process-group supervisor; if the web process exits or the supervisor stops, all three groups are stopped. Bare-metal systemd renders `Wants=` from the web unit and `BindsTo=ainews-web.service` on worker/Beat. `CELERY_IMPORTS` loads `tasks` for standard Celery CLI worker registration. These ownership contracts are regression-tested; target-host Beat restart/recovery and Linux systemd stop propagation remain C05 runtime evidence gates. See `docs/operations.md` for the supported start/stop lifecycle.
- Current-branch scheduled-edition smoke (2026-10-30): separate Beat and solo-pool worker processes used an isolated Redis broker and disposable SQLite DB; a due unified `main` profile produced a completed occurrence and one published edition item. Both email gates were off and there were no delivery intents. This verifies one ordinary local-time slot through Beat dispatch and worker execution; it does not qualify restart recovery, multiple simultaneous slots, DST execution, two-worker contention, or the intended host.
