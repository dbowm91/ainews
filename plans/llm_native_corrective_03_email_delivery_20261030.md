# C03 — Email distribution RFC compliance, outbox lifecycle and safe retries

**Status:** PLANNED / OPEN; P0 before any real newsletter fanout.
**Parent:** [corrective pass](llm_native_corrective_pass_overview_20261030.md).
**Dependency:** M3/M4 implementation exists on PR #20. C01 needed for deployment. C03 may be coded independently of C02.
**Default:** global and per-profile email delivery remain OFF until targeted tests and intended-host rehearsal are complete.

## Source-backed defects and risks

- services/email.py send_newsletter_email() sets the List-Unsubscribe header to an HTTPS URL but sets List-Unsubscribe-Post to the literal "One-Click". For RFC 8058 one-click behavior the required value is **List-Unsubscribe=One-Click**; retain the proper List-Unsubscribe HTTPS URL and the exact form POST handler. Merely changing a test string without inspecting the serialized MIME message, DKIM signing policy and sender/domain headers is insufficient for real delivery eligibility.
- services/distribution/dispatch.py owns durable per-recipient DeliveryIntent/DeliveryAttempt, leases, temporary-failure retry, unknown-outcome reconciliation and opt-out rechecks. The design is correct in direction, but actual worker death between SMTP acceptance and commit cannot be fully established by mocked successful sends; an unknown state must never be automatically retried. Reconcile stale claims after a worker crash.
- services/distribution/email.py catches TimeoutError/ConnectionError/SMTP exceptions and returns typed outcomes; review connection-close, exceptional MIME/header construction, and transport acceptance ambiguity. services/email.py _send_smtp() closes/returns pooled sessions differently by failure path. Verify connection and exception taxonomy on fake server and network disconnect fixtures, not only monkeypatched return values.
- tasks/newsletter.py generate_edition publishes then creates outbox rows and asynchronously dispatches tasks; manual publish+send does something similar. A crash after edition publication but before delivery-intent generation can strand an otherwise published edition. The system needs a recoverable *distribution planning* state/periodic reconciliation without creating duplicate deliveries. Do not make SMTP a prerequisite for publication.
- tests/test_llm_native_publication.py covers a small fake-SMTP message and outbox scenarios; target-instance SMTP, subscriber volume, lease contention and recipient opt-out during fanout were not verified.

## Corrective implementation

1. Update services/email.py to emit correct RFC 8058 List-Unsubscribe and List-Unsubscribe-Post headers. Verify the supplied unsubscribe link has an HTTPS origin in any externally delivered one-click email; use trusted configured SITE_URL or NEWSLETTER_SITE_URL and never request Host. Preserve safe human GET confirm behavior if implemented while POST on List-Unsubscribe=One-Click deterministically deactivates the subscribed newsletter type. Document signed/token security, DNS/HTTPS and DKIM requirements (one-click headers need suitable DKIM coverage). Validate SMTP provider behavior rather than asserting mailbox clients must expose a one-click button.
2. Add a durable reconciliation seam between published NewsletterEdition and planned DeliveryIntents. A published edition can exist with email disabled; a send-enabled edition should persist a distribution request/intention (with profile/channel policy snapshot) **only when explicit send was requested**, before fanout. Repeated planning must be idempotent on (edition_id, channel, subscriber_id). A worker or periodic reconciliation should finish a recoverable pending plan if enqueue fails, respecting the original send intent. Never start live fanout just because the global email toggle is enabled later; past editions without a send request must remain unsent unless explicit admin action.
3. Make every attempt state transition precise: pending -> claimed -> accepted / failed (retryable) / permanent_failure / suppressed / unknown. Implement lease-owner or compare-and-swap protection where a stale worker could overwrite another attempt's newer state. Apply attempt_count, next_attempt_at and claim expiry atomically; record sanitized SMTP status and timestamps. Keep DB transaction closed over SMTP I/O. Test at-least-once Celery delivery and duplicate task invocations.
4. Clarify SMTP acceptance and retry policy: accepted means remote SMTP accepted the message, not inbox delivered; unknown after possible acceptance must hold, not auto-retry. "retry_unknown" admin action requires explicit acknowledgment and shows duplicate risk. Only unambiguous retryable 4xx fail automatically within the five-attempt cap and bounded backoff. Stop on permanent 5xx, unsubscribe or missing recipient.
5. Harden opt-out while many tasks are queued: recheck subscriber verification/active/deleted immediately before transport; recheck global+profile send gate at admission and when claiming pending intents, with an explicit cancellation policy for disabling an already-running campaign. Do not silently continue after a disable action unless admin explicitly chose "finish queued sends." Define and test this policy, including manual cancel and resumed worker cases.
6. Review privacy and resource limits: subscriber token and recipient email may be present only in personalized outbound message; never in edition/API/MCP snapshots, public HTML, request logs, exception traces or permanent attempt rows. Limit concurrency, SMTP pool, batch query count and destinations on low-memory machines. Avoid sending entire recipient population twice on retries.
7. Update operational docs to separate publishing, send authorization, pending planning, SMTP accepted, unknown and operator retry/cancel. The existing main/category subscriptions and transactional welcome/verification email should remain untouched by edition outbox migration.

## Required regressions and operational fixtures

- **RFC message test:** capture actual message serialized by _send_smtp, parse with Python email parser and assert one List-Unsubscribe HTTPS URI bracketed, exact List-Unsubscribe-Post: List-Unsubscribe=One-Click, MIME-safe subject, correct recipient and no header injection. Test one-click POST's exact form semantics with CSRF policy appropriate for external email-client POST, while browser admin mutations remain CSRF-protected. Confirm signing/headers on the intended SMTP relay separately.
- **Recipient safety:** verified main and category subscriber segregation, unverified/deleted/unsubscribed exclusion, unsubscribe during queue-to-send, profile/global toggle off before claim and before send, no implicit enrollment into other profiles.
- **Crash matrix:** worker exit before SMTP, timeout before acceptance, SMTP 250 then worker dies before commit, delivery task enqueued twice, stale 10-minute lease, process restart after edition publication before delivery planning; ensure accepted/unknown accounting, no silent resend and resumable send requests only.
- **Failure taxonomy:** 4xx retry next_attempt_at, permanent 5xx terminal, disconnect ambiguous, unexpected exception sanitized, backoff maximum 5, idempotent per-intent retry and cancellation; manual retry_unknown confirmation audited.
- **Volume:** fake local SMTP sink and genuine Celery worker+Redis broker exercising 100, 500 and optionally 5,000 recipients under configured caps, no real subscriber traffic. Record throughput, memory, connection count and lease contention; avoid claiming exactly-once delivery.
- **Disabled path:** no SMTP configured, two editions published with no subscriber and global/profile email off, safe preview/test-only message. Public archive remains identical throughout transport errors.

Document how ambiguous outcomes are handled, exact tests, SHA, and operator enablement/rollback procedure. C05 supplies final target-instance evidence.
