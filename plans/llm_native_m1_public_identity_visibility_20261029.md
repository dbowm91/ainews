# M1 — Public article identity, publication visibility and safe read model

**Status:** PLANNED
**Parent:** [LLM-native roadmap](llm_native_publication_roadmap_20261029.md)
**Priority:** P0 safety prerequisite to agent read access. Can run parallel with M3.

## Objective

Keep integer Article.id as an internal relational primary key, introduce collision-resistant public identity, and make one explicit published-content boundary govern HTML, feeds, search, newsletters, public API, and MCP.

## Evidence to reproduce

models/article.py: Article.id is db.Integer primary key; short_id is nullable string with uniqueness but is not an identity secrecy guarantee. models/utils.py: encode_short_url() encodes the integer deterministically. routes/public/links.py: /article/<int:article_id> loads without checking publication state, and /s/<short_id> redirects to numeric URLs. templates/partials/share_macro.html falls back to article.id for a missing short_id, which /s lookup cannot necessarily resolve. services/article.py, services/search/sqlite_fts.py, services/search/hybrid.py and routes/public/feeds.py include done/skipped in public result paths; review whether skipped represents intentionally published material, and do not accidentally expose draft/review items. Confirm current status transitions and historical links before migration.

## Data and migration contract

1. Add Article.public_id, String(32) or equivalent, unique and indexed, generated by cryptographically secure secrets.token_urlsafe(16) (128-bit entropy). Do **not** derive it from ID, timestamp, slug, hash of predictable attributes or short_url. New creation code generates once; a unique-index collision retries. Never rotate an existing public ID when the article is edited.
2. Add idempotent batched backfill for all existing rows; preserve integer PK/FK relationships. New column nullable during transitional schema creation, backfill under migration, then enforce non-null when supported by SQLite migration strategy. Validate collision count, row count, restartability and backup/restore against SQLite/WAL.
3. Define a publication service or query predicate such as published_article_query() and is_publicly_visible(article). Clarify statuses: DONE must also satisfy explicit visibility and available final content; SKIPPED should *not* expose selector internals by default. Handle scheduled review, deleted/tombstoned items, reprocessing, and admin overrides. If a published article re-enters a draft state, define and test whether the prior published version remains visible or is temporarily withdrawn. Avoid relying on created_at alone for public chronology.
4. Provide a public article serializer and canonical URL builder, returning a stable typed DTO with public_id, headline, TL;DR, why_it_matters, body, category, tags, publication timestamp, canonical URL, citations and permitted source attribution. Keep raw extracted_text, research_brief, drafts, pipeline status/review details, internal keys, API/admin token metadata and private audit records absent.
5. Share a stable read/query seam between website, RSS, search, public API, MCP and newsletter selection. Keep application layers: services can query models; adapters do not import services; views are thin controllers.

## External link policy (requires deliberate migration)

Make /article/<public_id> canonical and use public_id in HTML, JSON-LD, RSS GUID/link, sitemap, related items, shares, newsletter URLs and public API. Reconcile old /article/<int:id>, /s/<short_id>, /a/<short_id> and newsletter-click links without silently breaking known historical shares. Any public numeric lookup makes sequential enumeration possible even if it redirects; there is **no** way to have both complete legacy numeric URL resolution and a guarantee that numeric enumeration cannot work. Document a finite compatibility option (e.g. temporary read-only redirects with throttling) and an explicit hardened mode disabling numeric external resolution. The admin may retain internal numeric routes under authentication. If preserving existing short IDs, do not claim they are random.

Avoid leaking canonical numeric IDs in response bodies, redirect Location headers, HTML data attributes, share DOM, OpenAPI examples or structured data. Avoid treating non-guessable URLs as authorization: intentionally listed public content remains crawlable.

- docs/api.md and public URL migration notes; do not change authenticated admin IDs gratuitously.

## Acceptance suite and gates

- A pre-fix regression reproduces unauthorized access to unfinished/failed/review article by known numeric ID and demonstrates an enumerability path. Both return 404 (or an approved privacy-preserving response) in hardened mode.
- New IDs are unpredictable with 128 bits of entropy; 100k-generation synthetic test has no collisions; test intentionally mocked collision handling and reusing an existing ID after edit.
- Fresh DB and upgraded representative SQLite copies converge, keep FKs, preserve article count and do not change original article data; rollback behavior is documented. Do not run destructive migrations against original target data.
- For every public surface, only the same set of publicly visible articles appears. Search results, tag/category routes, RSS, sitemap, public detail, API/MCP all agree. Hidden rows must not leak via counts, snippets, serialized related links or caching.
- A click from feed to detail, share, related, RSS and newsletter resolves with a public ID; legacy route tests cover chosen compatibility mode.
- URL-generation helpers and publication service have focused unit tests; integration tests cover N+1 query ceilings, bounded responses, cache invalidation and adequate local throughput.
- **Stop** if publication semantics remain ambiguous: define them before publishing a machine API. Document what historical URLs will cease to work; do not label an encoding as cryptographic randomness.

## Deliverable

A migration-backed read model with consistent publication semantics and random external identifiers, independent of REST/MCP transport. Add an implementation evidence section and change status only after tests and intended-instance migration rehearsal.
